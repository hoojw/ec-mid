## 第五轮：活动核算接 ec_dw，并加粗算 / 精算切换（2026-11-26）

`/activity` 原先读 `activity`、`activity_item`、`product`、`store` 四个原型表，重构后表已删，整页 500。本次重写为只读 `ec_dw`。

- 新增文件 `activity-calc.js`：取数 + 两种口径的计算，页面路由只做渲染
- 筛选栏：平台 / 店铺 / **口径（精算、粗算）**
- 精算：`档位毛利 = 销售额 − 技术服务费 − 冷链费 − 包装费 − 0.1 + 买家支付邮费 − 订单平均运费 − 多盒承担 − 订单药品成本 − 利润点 − 代运营费`，`毛利期望值 = 档位毛利 × 出现概率`，`毛利值 = SUM(毛利期望值) PARTITION BY 记录日期, 活动类型, 商品名称`（在 JS 内按商品 × 活动聚合）
- 粗算：取出现概率最高的运费档位单档，只扣药品成本、技术服务费（销售额 × 平台扣点）、订单平均运费，不做概率加权
- 字段映射：`门槛价格` = subsidy.`补贴门槛`（平台要求降到该价才给补贴的目标到手价，**不是当前售价**，页面并排展示 `当前售价`）；`门槛盒数` = `门槛数量`；`补贴承担` = `商家承担`；`订购盒数 / 出现概率 / 订单平均运费` = input_freight；`成本价` = input_cost；`平台扣点 / 利润点 / 代运营费率` = merchant_profit_setting（按生效日期取当期版本）
- 出现概率在 input_freight 里存的是 0~1 的小数（同一货品各档位合计约 1.0），页面按百分比展示

已知数据边界：

- 只有美团有门槛价；京东、天猫的补贴目录按平台维度采集，`客户` 为空，无法按店铺核算（页面直接说明无可用数据）

## 第六轮：精算逐项展开、粗算改红线价口径（2026-11-26）

### 精算：按档位逐项列出

汇总表右边新增「逐项」列，点进去在下方按 `ec_dw.input_freight` 的每个订购盒数档位渲染一张卡片（原型 `.co` 行式：左项目名 + 小字算式，右金额），逐项为：销售额、订单药品成本、技术服务费、多盒承担、包装费、冷链费、损耗费、买家支付邮费、订单平均运费、利润点、代运营费、档位毛利、毛利期望值。默认选中毛利值最低的「商品 × 活动」，链接带 `act_detail=<商品编码>|<活动名称>`。原 19 列宽表改为「档位明细宽表」折叠保留。

`activity-calc.js` 的 tiers 增加 `merchant / discount / buyer / feeRate / profitRate / agencyRate` 供算式回显。

### 粗算：改为红线价口径

```
总成本 = 药品成本(成本价 × 盒数) + 固定运费(普通 3.00，冷链 20.00)
红线价 = 总成本 ÷ (1 − 平台扣点 − 代运营 − 利润点)
毛利   = 门槛价 × 盒数 − 红线价
毛利率 = 毛利 ÷ (门槛价 × 盒数)
```

- 档位仍取出现概率最高的那一档单档，盒数见列
- 冷链判定沿用精算：品名含 替尔泊肽/瑞佰安/瑞百安/诺和盈/诺和泰
- **口径说明**：需求原话是「除以（技术扣点+代运营+利润点）」，直接除费率合计（9%）会得到成本 11 倍的数值，不是保本价；费率是从售价里扣的，所以按 1 − 费率合计 还原，即成本 ÷ 0.91
- 不再扣除订单平均运费、包装、损耗、买家邮费、多盒承担，也不按概率加权
- 表格列改为：药品成本 / 固定运费 / 总成本 / 费率合计 / 红线价 / 毛利 / 毛利率

粗算口径下保民 · 美团 · 2026-11-26：66/140 可算，毛利合计 -1,150.77，负毛利 65 个。

备份：`/opt/ec-mid/backups/activity_items_20261126/`（server.js、activity-calc.js、style.css）
